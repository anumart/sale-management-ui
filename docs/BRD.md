# Business Requirement Document (BRD)

**ระบบ**: Bangkok Flower Sale Management System (ระบบจัดการขาย จัดซื้อ ผลิต และขนส่ง ดอกไม้)
**เอกสาร**: BRD v1.0
**วันที่**: 2026-10-30
**สถานะ**: Draft สำหรับทบทวนร่วมกัน (business + ทีมพัฒนา)
**เอกสารอ้างอิง**: `PROCUREMENT_SYSTEM_SPEC.md` · `PROCUREMENT_SYSTEM_DESIGN.md` · `ERD.md` · `DFD.md` · `DESIGN.md`

> เอกสารนี้สรุป **ความต้องการทางธุรกิจ** (ทำอะไร ทำไม ใคร กฎอะไร) ไม่ลงรายละเอียดเชิงเทคนิค — รายละเอียดการออกแบบตัวแทนข้อมูล หน้าจอ และ API อยู่ในเอกสารอ้างอิงข้างต้น

## 1. วัตถุประสงค์

บริษัทดอกไม้ (Bangkok Flower) ดำเนินธุรกิจขายดอกไม้ 3 แบบ คือ ฝากขาย ขายขาด และส่งออก โดยปัจจุบันกระบวนการทำงานกระจายอยู่ในหลายช่องทาง (อีเมล ไฟล์ excel โทรศัพท์ กระดาษ) ทำให้เกิดปัญหา:

1. **ยอดสั่งซื้อกับยอดผลิต/จัดซื้อไม่เชื่อมกัน** — สั่งวัตถุดิบจากความรู้สึก ไม่จากข้อมูลยอดขายจริง
2. **ไม่รู้ของจริงที่รับเข้า** — รับของจากสวนแล้วจำนวนไม่ตรงที่สั่ง ไม่มีระบบบันทึกความแตกต่าง (variance)
3. **งานส่งของพึ่งคน** — ใบส่งของ ใบเข้าร้าน ยอดฝากขาย คิดมือบนกระดาษ
4. **ไม่มีประวัติตรวจสอบได้** — ใครแก้ยอด แก้เมื่อไร ตรวจสอบย้อนหลังไม่ได้

**เป้าหมายของระบบ**: ให้ทีมจัดซื้อ ผลิต ขนส่ง และขาย ทำงานบนข้อมูลชุดเดียวกัน ตั้งแต่รับยอดขายจนถึงวางบิล และสามารถตรวจสอบย้อนหลังได้ทุกขั้นตอน โดยระบบที่ "เตือน" ให้ตัดสินใจ 而非 ตัดสินใจแทนคน (หน้างานจริงต้องยืดหยุ่น)

## 2. ภาพรวมธุรกิจ

### 2.1 วงจรการขายรายวัน (Order-to-Cash ต่อวันส่ง D)

| ช่วงเวลา | กิจกรรม |
|---|---|
| ก่อนวัน D (ล่วงหน้า) | วางแผนจัดซื้อจากยอดขายย้อนหลัง (ฝากขาย+ขายขาด) + คำสั่งซื้อส่งออกแน่นอน (platform สั่งล่วงหน้า) |
| D-1 เช้า | คัดกรองคำสั่งซื้อจากอีเมล/ไฟล์ → ยืนยันคำสั่งซื้อ (โทรสั่งคีย์ได้ตลอด) · ทำ "ยอดประเมินลงร้าน" ทุกสายที่วิ่งวัน D → ยืนยัน |
| D-1 บ่าย (หรือเมื่อไหร่ก็ได้) | วางแผนผลิตตามวันส่ง D = ยอดประเมินทุกสาย + คำสั่งซื้อ confirmed ที่ส่งวัน D → ออกใบสั่งผลิต → ผลิตเป็น LOT (LOT ถูกกันไว้ให้สาย/คำสั่งซื้อนั้น) |
| เช้าวัน D | วิ่งรถรับวัตถุดิบ (ใบวิ่งรถ) → บันทึกรับของจริง + variance |
| วัน D | ออกใบส่งของ (สายฝากขาย หรือ ส่งตรง — ไม่ปนกัน) → คนขับส่ง + ใบเข้าร้าน (สแกน/เซ็น) → ของคืนเข้าสต็อก |
| หลังส่ง | ฝากขาย: ยอดขายจากร้าน → ใบแจ้งหนี้ · ขายขาด: ใบแจ้งหนี้ตามที่ส่ง · ส่งออก: commercial invoice + packing list (อังกฤษ) |

### 2.2 สามช่องทางขาย

| | ฝากขาย (Consignment) | ขายขาด (Fixed order) | ส่งออก (Export) |
|---|---|---|---|
| รับยอด | staff ประเมินต่อสาย — **ไม่ใช่คำสั่งซื้อ** | อีเมล/ไฟล์ (คัดกรองแล้ว) หรือโทร | คีย์จาก platform ซื้อขายดอกไม้ |
| เอกสารตั้งต้น | ยอดประเมินลงร้าน (ConsignmentEstimate) | คำสั่งซื้อ (CustomerOrder) | คำสั่งซื้อ (CustomerOrder) |
| ยอดจริง | ของที่สแกนลงร้าน + ยอดขายจากร้าน | ตามคำสั่งซื้อ | ตามคำสั่งซื้อ |
| สั่งผลิต | 1 ใบต่อ สาย × วันส่ง × สินค้า | 1 ใบต่อ คำสั่งซื้อ × สินค้า | 1 ใบต่อ คำสั่งซื้อ × สินค้า |
| จัดส่ง | ใบส่งของแบบสายฝากขาย | ใบส่งของแบบส่งตรง | ใบส่งของแบบส่งตรง (ปลายทางสนามบิน) |
| เก็บเงิน | ใบแจ้งหนี้จากร้าน (GP ❓ค้าง) | ใบแจ้งหนี้ตามที่ส่ง | เอกสารส่งออกจากระบบ (❓ค้าง) |

## 3. ขอบเขตระบบ

### 3.1 อยู่ในขอบเขต (In Scope)

| โมดูล | เนื้อหา |
|---|---|
| ข้อมูลหลัก (Catalog) | สินค้าสำเร็จรูป + สูตร (BOM แบบมีเวอร์ชัน) · วัตถุดิบ (SKU) · ตระกูลวัตถุดิบ · หมวดหมู่ · ซัพพลายเออร์ + จุดรับ + แคตตาล็อกที่ขาย |
| จัดซื้อ | แผนจัดซื้อ (จากยอดขายย้อนหลัง/คำสั่งซื้อ/เลือกเอง) · ประมาณวัตถุดิบจาก BOM · เลือกซัพพลายเออร์+จุดรับ (บันทึกผลโทรศัพท์) · สร้างใบสั่งซื้อ (1 ใบ ต่อ Supplier+Route) · ติดตามสถานะ |
| ขนส่ง – ขารับ | รถ · เส้นทางรถ (ลำดับจุดรับ + วันที่วิ่ง) · ออกใบวิ่งรถ (จับ PO ตามจุดรับ) · พิมพ์ · บันทึกรับของจริง + variance → ปิดใบ |
| ขนส่ง – ขาส่ง | ใบส่งของ 2 แบบ (สายฝากขาย / ส่งตรง) · ของขึ้นรถ + ของคืน (สแกน LOT — เป้าหมาย) · จุดส่งสำเร็จ/ส่งไม่ได้ (มีเหตุผล) · งานวันนี้ของคนขับ (/my-jobs, มือถือ) |
| ผลิต | วางแผนผลิตตามวันส่ง (ความต้องการรวมทั้งสาย+คำสั่งซื้อ + สถานะว่าสั่งผลิตแล้วหรือยัง) · ใบสั่งผลิต (1 ใบ = 1 สินค้า = 1 LOT) · เริ่มผลิต/บันทึกผล/ปิดงาน · QC · คำนวณ yield · จด LOT (barcode, อายุ) |
| คลัง | สต็อกวัตถุดิบ (คงเหลือ/จอง/ความเคลื่อนไหว) · สต็อกสินค้าสำเร็จรูปราย LOT |
| ขาย | สายฝากขาย + ยอดประเมินลงร้าน (มียอดแนะนำ) · คำสั่งซื้อ (4 ช่องทาง + ผู้ซื้อต่างประเทศ) · นำเข้าจากอีเมล/ไฟล์ + map SKU · เข้าร้าน (ใบเข้าร้าน) · ยอดขายจากร้าน · ลูกค้า |
| วางบิล | ใบแจ้งหนี้ + รับชำระ · สรุปผลฝากขาย |
| ระบบ | ผู้ใช้/บทบาท/สิทธิ์ · เข้าสู่ระบบ (เบอร์โทร+รหัสผ่าน) · ตั้งค่าระบบ (เกณฑ์เตือน) · แจ้งเตือนในระบบ + LINE OA · Audit Log · โปรไฟล์ |

### 3.2 อยู่นอกขอบเขต (Out of Scope — รอบนี้)

- แอปมือถือ native (คนขับใช้เว็บบนมือถือ)
- GPS/เส้นทางอัจฉริยะ, บัญชีลูกค้าสัมพันธ์ (CRM) เต็มรูปแบบ
- บัญชี/การเงินเต็มระบบ (ระบบออกใบแจ้งหนี้เท่านั้น ไม่รวมบัญชีการเงิน ภาษีมูลค่าเพิ่ม/หัก ณ ที่จ่าย)
- ประติมากรรม/การผลิตอื่นที่ไม่ใช่ดอกไม้ (ระบบนี้ออกแบบสำหรับโรงดอกไม้โดยเฉพาะ)
- หลายบริษัท/หลายสาขา (single company)

### 3.3 เรื่องค้างที่ยังไม่ตัดสินใจ (Open — ❓)

| # | เรื่อง | ผลกระทบ |
|---|---|---|
| Q1 | ส่งออก: สกุลเงิน + ช่องทางรับเงิน | ใบแจ้งหนี้ส่งออก, รายงาน |
| Q2 | ส่งออก: การแพ็ก/กล่อง, phytosanitary, AWB/เที่ยวบิน, 1 เที่ยวหลายคำสั่งซื้อ | เอกสารส่งออก, การจัดส่ง |

## 4. ผู้ใช้และบทบาท (Roles)

ผู้ใช้ 1 คนมี 1 บทบาท · login ด้วยเบอร์โทร + รหัสผ่าน

| บทบาท | ใคร | ขอบเขต |
|---|---|---|
| `admin` | ผู้ดูแลระบบ | ทุกอย่าง + จัดการผู้ใช้ + ตั้งค่าระบบ + ดู Audit Log |
| `staff` | พนักงานทั่วไป (จัดซื้อ/ขาย/ขนส่ง/ผลิต) | ทุกอย่าง **ยกเว้น** จัดการผู้ใช้ ตั้งค่าระบบ ดู Audit Log |
| `driver` | คนขับรถ | งานวันนี้ของตัวเอง (ใบวิ่งรถ/ใบส่งของที่ถูกมอบหมาย) · ใบเข้าร้านที่ถูกมอบหมาย (สแกน, ให้เซ็น) — **ไม่เห็นราคา/ยอดเงิน** |
| `production` | พนักงานผลิต | ทำงานตามใบสั่งผลิต (เริ่ม/บันทึกผล/ปิดงาน) · เปิด-ปิดไลน์ซ่อม · ดูแผนผลิต คลัง สูตร |

หน้าแรกหลัง login: `admin`/`staff` → แดชบอร์ด · `driver` → งานวันนี้ (`/my-jobs`) · `production` → ใบสั่งผลิต

หลักการสำคัญ:
- **ตรวจสิทธิ์ที่ทุก API ไม่ใช่แค่ซ่อนเมนู** — เข้า URL ตรงแล้วไม่มีสิทธิ์ → หน้า "ไม่มีสิทธิ์เข้าหน้านี้"
- **ไม่มีการลบผู้ใช้** — ใช้ปิดบัญชี เพราะชื่ออยู่ในเอกสารย้อนหลัง
- เปลี่ยน role/ปิดบัญชี/รีเซ็ตรหัส = session ของผู้ใช้คนนั้นถูกยกเลิกทันที

## 5. ความต้องการเชิงธุรกิจ (Business Requirements)

เลขที่ requirements ใช้อ้างอิงในเอกสารอื่นได้ (BR-XXX-NN)

### 5.1 ข้อมูลหลัก — Catalog (BR-CAT)

| ID | ความต้องการ |
|---|---|
| BR-CAT-01 | สินค้าแต่ละ SKU เป็น raw material แยกกัน (ขนาด/เกรดต่างกัน = คนละ SKU) และอาจอยู่ภายใต้ "ตระกูล" (MaterialFamily) เพื่อรวมดูยอดของสายพันธุ์เดียวกัน |
| BR-CAT-02 | สูตรผลิต (BOM) เป็นแบบมีเวอร์ชัน: 1 สินค้ามีได้หลายเวอร์ชัน แต่มี **active ได้แค่ 1** — เปิดใช้เวอร์ชันใหม่ = เวอร์ชันเก่าถูกเก็บถาวรอัตโนมัติ ใบสั่งผลิตเดิมไม่เปลี่ยนตาม |
| BR-CAT-03 | วัตถุดิบที่ "ขายตรง" ได้ (ไม่ผ่านการผลิต เช่น ดอกขายเป็นกำ) ต้องแยก flag `isSellable` — ห้ามสร้าง finished good แบบมีสูตร 1 บรรทัดเพื่อเลี่ยง |
| BR-CAT-04 | ราคา/หน่วยที่ซัพพลายเออร์ขาย อยู่ระดับ "ซัพพลายเออร์" ไม่ใช่ระดับจุดรับ — ทุกจุดรับของซัพพลายเออร์รายเดียวกันใช้แคตตาล็อก/ราคาเดียวกัน |
| BR-CAT-05 | หมวดหมู่ (Category) สูงสุด 2 ระดับ ชนิดเดียวกัน (raw_material หรือ finished_good) — รายงานรวมหมวดพ่อต้องรวมลูกด้วย |
| BR-CAT-06 | ห้ามลบข้อมูลที่ถูกอ้างอิง (วัตถุดิบที่อยู่ใน BOM/PO/ใบสั่งผลิต, ตระกูลที่มี SKU) — ใช้ปิดการใช้งานแทน |

### 5.2 จัดซื้อ (BR-PROC)

| ID | ความต้องการ |
|---|---|
| BR-PROC-01 | สร้างแผนจัดซื้อได้ 3 ทาง: ยอดขายย้อนหลัง (เลือกเดือน/หมวด) · คำสั่งซื้อที่ยืนยันแล้ว · เลือกสินค้าเอง |
| BR-PROC-02 | แผนต้องแสดงสินค้าที่จะผลิต + จำนวน (ปรับได้) แล้ว**ประมาณวัตถุดิบที่ต้องใช้จาก BOM active** หักด้วยสต็อกคงเหลือ ณ ตอนสร้างแผน (snapshot) |
| BR-PROC-03 | บันทึกการสั่งซื้อ**ต่อซัพพลายเออร์** (1 สายโทรศัพท์ = 1 drawer (side panel) = 1 การบันทึก): แสดงวัตถุดิบในแผนที่ซัพพลายเออร์รายนั้นขาย · แต่ละรายการสั่งต้องระบุ**จุดรับ (Route)** ทุกครั้ง · วัตถุดิบเดียวกันรับหลายจุดได้ แต่ห้ามซ้ำ (วัตถุดิบ+จุดรับ) · วัตถุดิบที่ไม่สั่งกับรายนี้ ปล่อยจำนวนเป็น 0 = ข้าม · ไม่มีสถานะการโทร |
| BR-PROC-04 | หน่วยสั่งซื้อ = หน่วยของซัพพลายเออร์ (มัด/กล่อง/กระสอบ) เป็นจำนวนเต็ม — หน่วยฐาน ÷ หน่วยต่อแพ็ก ปัดขึ้น (ต้องการ 95 ดอก มัดละ 10 → สั่ง 10 มัด) · **สั่งเกินแผนได้ ระบบเตือนอย่างเดียว ไม่บังคับ** |
| BR-PROC-05 | สร้างใบสั่งซื้อ: **1 ใบ ต่อซัพพลายเออร์** (ซัพพลายเออร์ที่มีหลายจุดรับก็ยังเป็นใบเดียว) — แต่ละรายการในใบระบุจุดรับของตัวเอง ซึ่งมีที่อยู่/ผู้ติดต่อ/โทรศัพท์ของจุดนั้น จำนวนเงินรวม = ผลรวมรายการในใบ |
| BR-PROC-06 | ใบสั่งซื้อที่คีย์เอง (manual) สร้างได้โดยไม่ผ่านแผน |
| BR-PROC-07 | สถานะใบสั่งซื้อ: `ordered` → `received` (+ `cancelled`) — **ไม่ส่งใบสั่งซื้อให้ซัพพลายเออร์** เพราะตกลงรายการและวันรับของทางโทรศัพท์แล้ว · แก้ไขหรือยกเลิกใบสั่งซื้อได้จนกว่าจะยืนยันรับของ (แม้พิมพ์ใบวิ่งรถไปแล้ว) · ใบสั่งซื้อเป็น `received` เมื่อรายการทุกบรรทัดถูกตรวจรับแล้ว (ใบที่มีหลายจุดรับอาจรอใบวิ่งรถหลายใบ) |
| BR-PROC-08 | แผนจัดซื้อ **ยังไม่รวมยอดส่งออกเป็นยอดแน่นอน / ยังไม่ตัดยอด platform ซ้ำ** (⏳ รอทำ — ต้อง: คำสั่งซื้อส่งออก = ยอดแน่นอน ส่วนยอดประเมินจากประวัติห้ามนับช่องทาง platform) |

### 5.3 ขนส่ง — ขารับ ใบวิ่งรถ (BR-LOG-P)

| ID | ความต้องการ |
|---|---|
| BR-LOG-P-01 | รถ = ข้อมูลหลัก (รหัส ทะเบียน น้ำหนักบรรทุก) **ไม่ผูกคนขับ** — คนขับ (User role=driver) เลือกตอนออกใบ |
| BR-LOG-P-02 | เส้นทางรถ = ลำดับจุดรับ (แต่ละจุดชี้ไปที่จุดรับของซัพพลายเออร์) + วันที่วิ่ง — **ไม่ผูกกับรถ** รถคันไหนวิ่งเส้นทางไหนก็ได้ |
| BR-LOG-P-03 | ออกใบวิ่งรถ 1 ใบ = 1 เที่ยว (รถ + คนขับ + วันที่ + เส้นทาง) — **รถ/คนขับคนเดียวกันมีหลายใบต่อวันได้** ไม่ล็อก (ระบบแจ้งข้อมูลประกอบว่ามีกี่ใบ ไม่บล็อก) |
| BR-LOG-P-04 | ระบบจับใบสั่งซื้อเข้าจุดรับอัตโนมัติ: PO ที่มี (ซัพพลายเออร์+จุดรับ) ตรงกับจุดในเส้นทาง และสถานะ draft/confirmed |
| BR-LOG-P-05 | ไม่ระบุเวลาออกรับ — ลำดับเที่ยวของวันดูจากเวลาพิมพ์ใบ |
| BR-LOG-P-06 | พิมพ์ใบวิ่งรถ (A4) ให้คนขับ — ไม่แสดง/ไม่ต้องมีราคาในใบของ driver |

### 5.4 ขนส่ง — บันทึกรับของจริง (BR-LOG-R)

| ID | ความต้องการ |
|---|---|
| BR-LOG-R-01 | รับของจริงโดยพนักงาน (ไม่ใช่คนขับ) หลังคนขับกลับมา — กรอกจากใบกระดาษ |
| BR-LOG-R-02 | ต้องกดปุ่ม "คนขับกลับแล้ว — เริ่มบันทึกรับของ" อย่างชัดเจน (Printed → InProgress) — **ห้ามเปลี่ยนสถานะอัตโนมัติเพราะแค่เปิดหน้า** |
| BR-LOG-R-03 | กรอกจำนวนรับจริงรายรายการ + เหตุผลเมื่อต่างจากรายการที่สั่ง · ระบบคำนวณ variance (จำนวนจริง − จำนวนสั่ง) |
| BR-LOG-R-04 | บันทึกผลตรวจ**ทีละจุดจอด** ได้ (จุดนั้นต้องกรอกครบ) และไม่เปลี่ยนสถานะใบวิ่งรถ — ให้ทำงานขัดจังหวะได้ · จุดที่แก้หลังบันทึกต้องบันทึกซ้ำ |
| BR-LOG-R-05 | ยืนยันปิดใบต้องตรวจครบ**ทุกจุดจอด** (บันทึกแต่ละจุดแล้ว) และกรอกจำนวนรับจริงครบทุกรายการ · ห้ามรับของย้อนหลังใบวันหน้า |
| BR-LOG-R-06 | แถวที่รับน้อย/ไม่ได้รับ ต้องเน้นสีให้เห็นชัด (ต่ำกว่าที่สั่ง = ส้ม, ต่ำกว่า 20% หรือไม่ได้รับเลย = แดง) |
| BR-LOG-R-07 | รายการของใบสั่งซื้อผูกกับใบวิ่งรถตามจุดรับ (`run_sheet_id` ที่ระดับ line) · ตอนตรวจรับ จำนวนที่รับ default จากจำนวนสั่ง พนักงานแก้ได้ · ถ้าของที่จุดรับหมด คนขับซื้อวัตถุดิบอื่นแทนได้ ระบบบันทึกเป็นวัตถุดิบที่รับจริงโดยไม่ทับสิ่งที่สั่ง · เพิ่มบรรทัดนอก PO ได้ · ยืนยันครั้งเดียวจบ flow (PO → `received`) |

### 5.5 ขนส่ง — ขาส่ง ใบส่งของ (BR-LOG-D)

| ID | ความต้องการ |
|---|---|
| BR-LOG-D-01 | ใบส่งของ 1 ใบ = 1 เที่ยวส่ง: เลือกรถ + คนขับ + วันที่ + จุดส่งเรียงลำดับ (staff จัดเอง ลากเรียงได้) |

| BR-LOG-D-05 | เสร็จสิ้นอัตโนมัติเมื่อทุกจุด done/failed (แบบสายฝากขายต้องบันทึกของคืนก่อน) · ยกเลิกได้เมื่อยังไม่มีจุดไหน done |
| BR-LOG-D-06 | ของขึ้นรถ/ของคืน (สายฝากขาย): ตอนพิมพ์บันทึกของขึ้นรถต่อสินค้า (สแกน LOT) · คนขับลงของแต่ละร้านตามหน้างานได้ ไม่ต้องตรงยอดประเมิน · จบเที่ยว staff บันทึกของคืน (สแกน LOT) ของคืนเข้าสต็อก · แสดงส่วนต่าง ขึ้นรถ − ลงร้าน − คืน (เตือน ไม่บล็อก) |
| BR-LOG-D-07 | `driver` ไม่เห็นราคา/ยอดเงินในใบส่งของ |

### 5.7 ผลิต (BR-PRD)

| BR-PRD-05 | เบิกวัตถุดิบตาม BOM active ตอนเริ่มผลิต — วัตถุดิบถูกจอง (allocated) ตอนอนุมัติแผน และหักจากสต็อกจริงตอนเริ่มผลิต · ผลิตเสร็จคืนส่วนที่เหลือ/หักส่วนเกินตามที่ใช้จริง |
| BR-PRD-06 | ปิดงาน: บันทึกจำนวนผลิตจริง + ของเสีย + ผลผลิต (yield = จริง÷แผน) · QC ผ่าน/ไม่ผ่าน · สร้าง LOT (เลข barcode, วันหมดอายุ) LOT ที่ผลิตเสร็จ**ถูกกันไว้**ให้สาย/คำสั่งซื้อของใบนั้น |
| BR-PRD-07 | LOT ไม่มีเกรด A/B/C — yield ต่ำเป็นแค่การเตือน (เกณฑ์ `lowYieldPercent`) |
| BR-PRD-08 | ⏳ วางแผนผลิตอัตโนมัติ (AI: จัดอันดับตามเดดไลน์/กำไร/สต็อก) = target design ยังไม่ทำ — รอบนี้วางแผนด้วยคนบนหน้าจอเดิม |

| BR-SAL-09 | **สรุปผลฝากขาย**: อัตราของเสีย (ของเสีย÷ของส่งเข้าร้าน) ใช้เกณฑ์ `wasteWarnPercent`/`wasteDangerPercent` ระบายสี/จัดอันดับสาขาของเสียสูง (ต่กว่า `wasteMinDelivered` ไม่นับ) |

| BR-SET-01 | ค่าเกณฑ์เตือนที่ตั้งได้ (ค่าเริ่มต้น · ช่วง): `wasteWarnPercent` 10% · `wasteDangerPercent` 15% (ต้อง > warn) · `wasteMinDelivered` 100 · `receiptVariancePercent` 10% · `expiryWarningDays` 7 · `lowYieldPercent` 95% |

| BR-SET-04 | แก้ได้เฉพาะ admin · ตั้งค่าเป็นชุดเดียวทั้งระบบ (ยังไม่ตั้งทับรายหมวด/รายสินค้า) |

## 6. กฎธุรกิจสำคัญ (Business Rules สรุป)

| BR05 | BOM active ได้แค่ 1 ต่อสินค้า · ใบสั่งผลิตเดิมไม่เปลี่ยนเมื่อเปิดสูตรใหม่ |
| BR06 | วางแผนผลิตจากรายการประเมิน/คำสั่งซื้อ ไม่ใช่จากรายการที่ "สั่งไปแล้ว" แต่ยังไม่รับของจริง |

| BR09 | ไม่มีการลบผู้ใช้/ลบข้อมูลที่ถูกอ้างอิง — ใช้ปิด/ deactivate |
| BR10 | ยอดประเมินลงร้าน ≠ คำสั่งซื้อ ≠ ยอดขาย — สามอย่างนี้ห้ามสับสนในรายงาน |
| BR11 | LOT ไม่มีเกรด — yield ต่ำเป็นแค่เตือน |
| BR12 | ห้าม login ด้วยช่องทางอื่นนอกจากเบอร์โทร+รหัสผ่าน — LINE ใช้แจ้งเตือนเท่านั้น |

## 10. ภาคผนวก

### 10.1 คำศัพท์ (Glossary)

| คำ | ความหมาย |
|---|---|
| แผนจัดซื้อ (Purchase Plan) | แผนว่าจะผลิตสินค้าอะไรบ้างเดือนนั้น และต้องซื้อวัตถุดิบอะไรเพิ่ม |
| จุดรับ (SupplierRoute) | สวน/สถานที่ของซัพพลายเออร์ที่รถไปรับของ — 1 ซัพพลายเออร์มีได้หลายจุด |
| ใบวิ่งรถ (Run Sheet) | เอกสารขารับ: เที่ยวรถ 1 ครั้งไปรับของตามเส้นทาง (มีจุดรับหลายจุด จุดละ 0..N ใบสั่งซื้อ) |
| ใบส่งของ (Delivery Sheet) | เอกสารขาส่ง: เที่ยวส่ง 1 ครั้ง (สายฝากขาย หรือ ส่งตรง) |
| เส้นทางรถ (VehicleRoute) | ลำดับจุดรับประจำวัน ไม่ผูกกับรถ |
| สายฝากขาย (ConsignmentRoute) | เส้นทางขายฝาก: ร้านเรียงลำดับ + วันที่วิ่ง (ข้อมูลฝ่ายขาย ไม่เกี่ยวกับเส้นทางรถ) |
| ยอดประเมินลงร้าน (ConsignmentEstimate) | ตัวเลขที่ staff ประเมินว่าร้านนี้ควรวางสินค้าอะไรกี่ชิ้น — ไม่ใช่คำสั่งซื้อ |
| ใบเข้าร้าน (ConsignmentVisit) | เอกสารตอนเข้าร้าน: ลงของ + ของเสีย + ร้านเซ็น |
| LOT / FinishedGoodsBatch | งวดผลิต 1 ครั้ง = 1 สินค้า = 1 LOT (มี barcode อายุ) |
| Yield | อัตราผลผลิต = จำนวนจริง ÷ จำนวนแผน (%) |
| Variance | ผลต่าง รับจริง − สั่ง (รับของ) หรือ จริง − แผน (ผลิต) |

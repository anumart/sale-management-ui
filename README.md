# sale-management-ui

Front-end for the Sale Management system (property sales dashboard).

| Technology | Purpose |
|------------|---------|
| React 19 | UI framework |
| TypeScript | Type safety |
| Vite | Build tool / dev server |
| TanStack Router | Client-side routing (file-based) |
| TanStack React Query | Server state (fetching, caching, mutations) |
| Zustand | Client state (menus, toasts, confirm box) |
| Tailwind CSS v4 | Styling (design tokens in `src/styles/index.css`) |
| Axios | HTTP client |

UI rules live in **[DESIGN.md](DESIGN.md)**. Read it before building screens.

## Getting started

```bash
npm install
cp .env.example .env     # already done once; edit as needed
npm run dev              # http://localhost:5173
```

| Script | What it does |
|---|---|
| `npm run dev` | Dev server with HMR; regenerates `src/routeTree.gen.ts` |
| `npm run build` | Type-check (`tsc -b`) + production build to `dist/` |
| `npm run preview` | Serve the production build |
| `npm run typecheck` | Type-check only |

### Environment

| Variable | Default | Meaning |
|---|---|---|
| `VITE_API_URL` | `http://localhost:3000/api` | Backend base URL used by Axios |
| `VITE_USE_MOCK` | `true` | `true` = requests are answered by the in-memory mock API in `src/mocks`, so the app runs without a backend. Set it to `false` to call the real API. |

## Conventions

- **Server state goes through React Query, client/UI state through Zustand.** Don't copy API data into Zustand.
- **Each feature owns its `api.ts`.** It holds:
  - An `xxxApi` object with the Axios calls, using the shared `http` instance from `@/lib/http`.
  - `xxxKeys` query-key factories.
  - `useXxx` hooks (queries and mutations). Mutations invalidate their feature's keys.
- **Routes stay thin.** A route file only maps a URL to a page component in `features/*`.
- **Shared vs feature components:**
  - Reused across features and free of business logic: `components/ui`.
  - Knows about a domain (properties, notifications…): `features/<name>/components`.
- **Styling:** use Tailwind utilities with the tokens from `@theme`, and `cn()` for conditional classes. `cn()` also resolves Tailwind conflicts, so a `className` prop can override defaults.
- **Imports** use the `@/` alias for `src/`.
- **Confirm box:** every destructive action goes through it. Use `confirm()` or `<ConfirmDialog>`, then report the result with `toast.*`.

## Adding a page

1. Create `src/features/<name>/<Name>Page.tsx`, starting with `<Topbar title="…" />`.
2. Create `src/routes/<path>.tsx`:
   ```tsx
   export const Route = createFileRoute('/<path>')({ component: NamePage })
   ```
3. Add the nav item in `src/components/layout/Sidebar.tsx`.
4. Add API calls and hooks in `src/features/<name>/api.ts`. While there's no backend, add a mock handler in `src/mocks/handlers.ts`.
